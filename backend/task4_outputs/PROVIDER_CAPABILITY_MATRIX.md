|---|---|---|---|---|---|---|---|
| Google Gemini | `gemini-3.1-flash-image` | `google-genai` `client.models.generate_content(model, contents, config)` | `types.Part.from_bytes(...)`, inserted between an identity-anchor text part and the prompt | Image-to-image editing capability is supported by the model when text and image are supplied, but this call is a generative multimodal request—not a deterministic, masked product-retouch operation | No mask, selected region, seed, denoise/reference-strength, or preservation parameter is passed; the code sets only `response_modalities` and aspect ratio | Forced Gemini controlled test returned an image successfully. ## Evidence

- Repository: `backend/app/config.py`, `backend/app/ai/providers/gemini_image_provider.py`, `backend/app/ai/providers/openai_image_provider.py`, and `backend/app/ai/image_generation_manager.py`.
- Google: [Gemini image generation and editing](https://ai.google.dev/gemini-api/docs/image-generation) documents text-and-image-to-image editing and the current `gemini-3.1-flash-image` model. It describes multiple reference images, but does not document a denoise/reference-strength or mask field for the API request used here.
- OpenAI: [Image generation guide](https://developers.openai.com/api/docs/guides/image-generation) documents the edits endpoint for existing images, reference-image generation, and mask-based partial edits. It also documents `input_fidelity` for input-image detail preservation; the project does not supply it. [Images API reference](https://developers.openai.com/api/reference/resources/images) lists the supported image models and edit parameters.

“True edit” here means the provider supports image-to-image editing, not a guarantee of pixel-level or product-SKU-level preservation.
